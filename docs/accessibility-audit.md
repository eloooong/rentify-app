# Rentify Accessibility Audit (A4.1)

Audit of Person A's screens against WCAG 2.1 AA, with findings in Person B's screens reported for B to fix. Run on 19 November 2026 by Person A (Claude Code) on branch `fix/a11y-audit`, cut from `main` at `ac4ef51`.

## How it was tested

- **Stack:** local Supabase (Docker) with `db:demo` data and a production build (`next build` + `next start`). Not tested on the hosted test environment.
- **Accounts:** the demo renter and demo owner. Test data was created through the real app (a request, an acceptance, a chat message, a review). One expired booking was set to `completed` with local SQL so the review screens could be reached. Everything was removed or restored afterwards (see [Test data](#test-data)).
- **Automated:** axe-core 4.14 (the engine behind Lighthouse's accessibility score), run with the WCAG 2.0/2.1 A and AA rules plus best practices. Every route below was checked at 320 or 375 px and at 1280 px.
- **Manual:**
  - keyboard passes (tab order, focus traps, Escape, focus after actions), with the focused element's computed outline recorded at each step
  - headings and landmarks, accessible names, live regions, and error messages after real submits
  - reflow at 320 px (no horizontal scroll) and colour contrast of the tokens in `app/globals.css`
- **Routes:**
  - Header, mobile menu, skip link and footer
  - `/`, `/listings` (including filters and `?page=99`), `/listings/[id]` (including the 404 state)
  - `/owner/listings`, `/owner/listings/new` (empty submit) and `/owner/listings/[id]/edit`
  - `/bookings` (both sides), `/bookings/[id]` (requested, accepted, cancelled and completed with the review form), `/bookings/history`
  - `/checkout/[bookingId]` (consent error)
  - `/messages`, `/messages/[id]` (send)
  - `/notifications` (empty and with unread items)
  - `/reviews/[id]`
  - `/help`, `/help/terms`, `/help/privacy`, `/help/prohibited-items`
  - B's screens: `/login` (empty submit), `/signup`, `/forgot-password`, `/auth/error`, `/account`, `/checklists` and `/checklists/[id]/handover`. `/admin` is not built yet; it redirects to sign-in.

**axe result:** 0 violations on every route above, before and after the fixes. All the problems below were found by keyboard, not by axe.

### Checked and working

- **Skip link and landmarks.** The skip link is the first Tab stop and targets `<main>`. The `header`, `main`, `footer` and `nav` landmarks have names: Primary, Mobile, Footer, Breadcrumb, "Booking side" and "Filter by status". Every page has one `h1` and headings that don't skip levels.
- **Header and mobile menu.** On desktop the tab order follows the visual order. The mobile menu is a dialog: focus loops inside it, and Escape returns focus to "Open menu". Header targets are 44 px.
- **Confirmation dialogs.** They are labelled and described, trap focus, and close on Escape. Focus returns to the opener once the 100 ms close animation ends. (In the browser pane, animation frames are delayed, so focus looked lost for about a second while testing; it isn't.)
- **Availability calendar.** It uses one Tab stop with arrow keys and has full date labels. Selected days use `aria-pressed`, the month heading is a live region, and the price summary is a status region.
- **Listing editor.** Labels and fieldsets are correct, and only optional fields are marked. An empty "Publish" moves focus to the error summary, and each field has `aria-invalid` with its error linked through `aria-describedby`.
- **Notifications.** Rows have names like "Unread: New message…" and buttons like "Mark as read: <title>, <time>". The bell's name includes the unread count.
- **Reviews.** The rating is a keyboard radio group. Publishing moves focus to the review and announces it politely.
- **Chat.** Messages appear in a labelled list, and a polite region announces them.
- **Contrast.** All text and interactive tokens pass AA. The only sub-AA token, `--rentify-fg-muted` (4.3:1), is not used for text anywhere.
- **Reflow.** There is no horizontal scroll at 320 px on any audited route.

## Not covered

- No real screen reader (NVDA, VoiceOver or TalkBack) was used. Names, roles, live regions and focus were checked through the DOM, the accessibility tree and axe only.
- Windows forced-colours (High Contrast) mode and text-only 200% zoom were not checked. Reflow at 320 px covers 400% zoom.
- Not exercised, because the local data can't reach them:
  - multi-photo gallery navigation (each demo listing has one photo)
  - paid, refunded and handover states
  - the paid-cancellation result (A-4)
  - the refocus on the `/bookings` list page (A-3)
- The hosted test environment.
